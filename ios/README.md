# RemoteCam for iOS

The iOS client targets iOS 17 and newer and uses Swift 6, SwiftUI, AVFoundation,
VideoToolbox, Network.framework, CoreMotion, and ActivityKit. Background camera
capture is enabled on supported devices when the app links against iOS 18 or newer.

## Build

Open `RemoteCam.xcodeproj` in Xcode, choose your development team for the RemoteCam
target, then build for an iPhone. The simulator build and unit tests verify the UI,
protocol framing, and state management, but the simulator cannot validate capture or
hardware video encoding.

From Terminal:

```sh
xcodebuild -project RemoteCam.xcodeproj \
  -scheme RemoteCam \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  test
```

The checked-in Xcode project is generated by `Tools/generate_project.rb`. Only run
the generator after installing the Ruby `xcodeproj` gem; normal contributors do not
need that gem to build the app.

## Current implementation

- Bonjour discovery with validated Windows TXT identity, manual IP/port fallback,
  recent hosts, duplicate-interface handling, and reconnect with exponential backoff
- AVCapture multi-lens selection, 30/60 fps format negotiation, tap focus, zoom,
  exposure/ISO/EV, white balance, stabilization, and torch
- Low-latency H.264/HEVC VideoToolbox encode with Annex-B parameter sets on every
  keyframe and runtime bitrate changes
- Orientation, battery, and thermal telemetry; PC-controlled local preview saving
- Background-capable capture configuration and a visible Live Activity while live
- Swift 6 unit tests for CBOR, TCP framing, and persistence

Secure pairing, authenticated control/media encryption, and USB cannot be completed
from the current draft protocol alone. The exact backend work and joint protocol
decisions are tracked in [`docs/ios-backend-handoff.md`](../docs/ios-backend-handoff.md).

## Device verification

On 2026-07-28 the app and Live Activity extension built and signed successfully
against the iPhoneOS 27 SDK using the beta Xcode toolchain. That build was installed
and launched on a physical iPhone. This confirms signing, installation, and startup
only: camera capture, hardware encoding, background operation, sustained thermal
behavior, and the live Windows-consumer matrix still require manual verification.
